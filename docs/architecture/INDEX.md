# Codebase map

Descriptive, not prescriptive: where things are. How to do them is in the
skills under `.claude/skills/`, listed at the bottom of `CLAUDE.md`.

Read this before grepping the tree.

```text

│   │   ├── auth/            password hashing, session tokens, login backoff
│   │   ├── stacks/          discovery, path resolution, atomic file writes
│   │   ├── compose/         the only place that shells out to Docker

│   │   └── api/             routes and handlers

├── frontend/                React 19 + Vite + Tailwind 4 + shadcn/ui
│   └── src/
│       ├── App.tsx          session gate: login screen or dashboard
│       ├── lib/             typed API client, wire types, .env masking
│       ├── hooks/           SSE subscription, stack queries
│       ├── components/      dashboard, cards, dialogs, editors
```

## HTTP surface

Public:

```text
GET  /api/health                      liveness, used by HEALTHCHECK
POST /api/auth/login                  sets the session cookie
```

Everything below requires a session cookie; without one the answer is 401.

```text
POST /api/auth/logout
GET  /api/auth/me

GET  /api/stacks                      rescans the directory on every call
GET  /api/stacks/{stack}              adds per-service container detail

POST /api/stacks/{stack}/start        202 { operation_id }
POST /api/stacks/{stack}/stop
POST /api/stacks/{stack}/restart
POST /api/stacks/{stack}/update

GET  /api/stacks/{stack}/logs?tail=N
GET  /api/stacks/{stack}/logs/stream  SSE
GET  /api/stacks/{stack}/compose
PUT  /api/stacks/{stack}/compose      validate, then replace atomically
GET  /api/stacks/{stack}/env          404 when the file does not exist
PUT  /api/stacks/{stack}/env

GET  /api/operations/{id}
GET  /api/operations/{id}/stream      SSE: replay, then follow
```

Anything else under `/api` answers a JSON 404. Anything outside `/api` is
served from the built frontend, falling back to `index.html`.

Error body:

```json
{ "code": "validation_failed", "message": "…", "details": "…" }
```

`code` is stable and machine-readable, `message` is for a human, `details`
carries command output when there is any, and `retry_after_secs` appears on a
throttled login.

## Two request paths worth knowing

**An action.** `POST /api/stacks/{stack}/start` resolves the stack
(`paths::resolve` → `discovery::inspect`), refuses an ambiguous one, registers
an operation — 409 if that stack already has one — and returns `202` with an
id. A background task runs the action's Compose steps, streaming stdout and
stderr into the operation's buffer and broadcast channel. The browser opens
`GET /api/operations/{id}/stream`, which replays the buffer and then follows.

**A Compose save.** `PUT /api/stacks/{stack}/compose` stages the candidate
beside the target, runs `docker compose --file <staged> config --quiet` in the
stack directory, and only on success copies the current file to `<name>.bak`
and renames the candidate into place. On failure the staged file is dropped and
the response is a 422 carrying the validator's own output.

## Cross-cutting

- **State.** `AppState` in `backend/src/api/mod.rs` holds the config, the
  database handle, the login limiter and the operation registry. Cloned per
  request; everything inside is cheap to clone.
- **Errors.** Handlers return `ApiResult<T>`. `ApiError::Internal` logs its
  context and returns a bare "internal error", because that context can name
  filesystem paths.
- **Logging.** `tracing`, filtered by `SHIMAU_LOG` (default `info`). Startup
  logs the Compose version, and says loudly when the CLI is missing.
- **No stack state.** There is no table, cache or field anywhere holding a
  stack's status, its Compose content, or its `.env`. Every read goes to the
  filesystem or to Docker.
